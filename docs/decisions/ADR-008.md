# ADR-008: Kinematic backend design and cross-mode agreement (M4)

- **Status:** Accepted (GPU verification pending; see ADR-001)
- **Requirements:** FR-ENG-09, FR-AGT-06, FR-OBS-04, FR-DOM-07 (auto-USD), AC-X-01/02, NFR-01

## Decisions
- **One movement model for all modes.** Routing, occupancy, blocking and deadlock
  logic (ADR-007) run in deterministic Python in every mode. `kinematic` differs
  from `logical` only in the backend: agent transforms are written to a USD stage
  at each fixed step (default 0.5 s, `--step`), with heading from the active
  segment. Consequently the kinematic event log equals the logical one except for
  the `sim.start` record, and AC-X-02's tolerance is met at 0% in CPU tests. The
  10% tolerance in AC-X-02 is kept for the real-Isaac test and for the later
  `physics` mode, whose PhysX-driven motion will differ.
- **Narrow stage surface.** `compat.StageAPI` (open, build_floor, add_agent,
  set_pose, update, save, close) is the only contract with Isaac; `IsaacStage`
  implements it with `isaacsim.SimulationApp` + `omni.usd` + `pxr` imported
  inside methods. CPU tests use a fake stage with the same methods.
- **Assets.** Plug-ins map agent types to USD assets (`asset_bindings`);
  `placeholder://...` (BRD Q4) produces a capsule sized from the footprint. The
  behaviour layer never sees assets (FR-AGT-06).
- **Minimal scene.** When the manifest has no `usd_stage`, zones become floor
  meshes and edges thin boxes, so no 3D asset is needed to start.
- **Replay.** `simcore.core.obs.replay` rebuilds trajectories from `agent.move`
  records (`source`, `target`, `entry`, `arrive`); `adapters.omniverse.replay`
  drives a stage from them. Positions match the live backend at sampled times.

## Not verified here
The container has no GPU or Isaac Sim, so `IsaacStage` is unexercised. The
`isaac`-marked tests (AC-X-01 headless reference run; AC-X-02 10% KPI agreement)
must be run on the target machine (`make test-isaac`) and this ADR updated with
the results and any API changes in the shim.
