# ADR-004: M1 reference scenario and the warehouse placeholder

- **Status:** Superseded by M3 (the warehouse plug-in is now the real reference domain; AC-ENG-01/02 run on `examples/scenarios/warehouse/baseline.yaml` as well)
- **Requirements:** AC-ENG-01/02/03, BRD 9, BRD 12 (M1 vs M3)

## Context
AC-ENG-01/02 speak of "the reference scenario" and AC-ENG-03 needs the toy
domain to load *alongside the warehouse plug-in*, but the warehouse domain
(facility, navigation, interaction) is scheduled for M3.

## Decision
- Until M3, the reference scenario for AC-ENG-01/02 is
  `examples/scenarios/toy_queue/mmc_baseline.yaml` (M/M/3, rho = 0.8). M3 switches
  the reference to the warehouse baseline and re-runs both criteria.
- `domains/warehouse` ships an M1 placeholder: a pick → stage loop with sampled
  travel times (`params.travel_time`) and its own KPI and disruption type, so
  AC-ENG-03 is exercised with two genuinely different plug-ins. M3 replaces the
  sampled travel with nav-graph travel and the interaction model.

## Consequences
- Warehouse KPIs before M3 are not meaningful operationally; the plug-in reports
  version `0.0.1` and describes itself as a placeholder.
