# ADR-012: Semantic layer and chart rendering (M8)

- **Status:** Accepted
- **Requirements:** FR-SEM-01..05, FR-VIZ-01..06, AC-SEM-01, AC-VIZ-01

## Decisions
- **Engine.** One in-memory DuckDB database per experiment: `results`, `runs` and
  (lazily) `events` tables are *copied* in, so queries never touch the filesystem;
  advanced SQL mode then disables external access and locks the configuration.
- **Metrics.** `source: kpi` metrics read one KPI key per replication. `source:
  event_log` metrics use a closed grammar (`count(type)`, `sum|mean|max|min(type.field)`,
  `@dwell`, `state_duration`, `state_intervals`); no free-form SQL by default. Core
  event metrics (completions, blocking time, edge occupancy, state time, ...) are in
  the core catalog; domains add their own in `domain.yaml`.
- **Aggregation.** Values are computed per (variant, replication, dims), zero-filled
  for counts/sums, then aggregated with Student-t intervals unless `replication` is a
  dimension. Comparisons are paired (CRN) or Welch vs a baseline. Results are wide:
  `<metric>`, `<metric>.ci_low|ci_high|n`, `<metric>.diff|diff_ci_low|diff_ci_high|
  ci_excludes_zero`.
- **Provenance + ref ids.** Each result has job id, variants -> config hashes, seeds
  per replication, domain/engine versions, git SHA, mode, data digest and the query;
  `ref_id = q_<hash(query, data digest, job)>`, stable for identical queries (used by
  the chat grounding check in M10).
- **Charts.** `ChartSpec` cannot hold data (schema `extra=forbid`); validation adds
  catalog checks, encoding-field checks, per-template requirements and the
  uncertainty guardrail; every problem carries path, suggestion and allowed values
  (repair-ready). Rendering emits Vega-Lite v5 with data from the governed query only;
  all 15 templates are verified by compiling to SVG with `vl-convert` in tests.
  Floor-plan overlays draw edges as rules and locations as circles and add a slider
  over time buckets. Exports: CSV, chart/provenance JSON, Vega-Lite, SVG, PNG.
