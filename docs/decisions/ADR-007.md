# ADR-007: Movement and interaction model (M3)

- **Status:** Accepted
- **Requirements:** FR-INT-01..07, FR-FAC-02/03, AC-INT-01/02, NFR-01

## Context
Congestion must come from geometry and kinematics, stay deterministic and fast in
`logical` mode, and be hand-calculable for AC-INT-01.

## Decisions
- **Link-entry speed.** An agent's speed on an edge is fixed when it enters, from
  the free speed (profile x per-agent multiplier x domain speed modifier x edge
  degradation, capped by `max_speed`) and the occupants present at that moment:
  `v = v_free * max(min_factor, (1 - alpha * others_width / width) * passing?)`,
  where `passing_speed_factor` applies only if an opposing or stationary agent is
  on the edge. Agents entering later do not re-time those already on the edge.
- **Lanes and passing.** `lanes = floor((width + clearance) / (footprint + clearance))`;
  passing (opposing or around a stationary agent) needs
  `width >= w1 + w2 + clearance`. Single-lane edges keep FIFO order; a follower
  exits no earlier than `leader exit + headway`, headway defaulting to
  `(own length + clearance) / own free speed`.
- **Holding.** An agent that reached the end of an edge but cannot enter the next
  keeps occupying its edge (that is what makes deadlocks possible).
- **Corridor reservation.** Edges joined by pass-through (degree-2) nodes form a
  corridor. Before entering one, an agent checks the whole stretch it will
  travel for oncoming agents it cannot pass. Without this, narrow aisles livelocked
  (8,359 deadlocks, 67 of 606 tasks done in the narrow warehouse test).
- **Fairness.** A newcomer does not enter a corridor against an agent that has
  waited longer to come through it the other way. This is a *soft* dependency: it
  is part of the wait-for graph, and a cycle through it is broken by waiving the
  deference, never by backing an agent out. Corridor waiters are woken by any
  release along their reserved stretch (a lost wake-up bug here caused hour-long
  starvation before the fix; regression test included).
- **Deadlocks.** On each new wait the wait-for graph is searched from the waiter
  (deterministic DFS). Strategies: `priority_yield` (default; lowest
  `priority` attribute, then highest id, reverses along its held edge, then
  re-plans), `reroute` (same, avoiding the contested edge when an alternative
  exists), `timeout` (yield after the configured delay if still deadlocked),
  `none` (log an unresolved `interaction.deadlock` record, fail the agents,
  requeue their tasks, continue the run). Reversal is allowed on one-way edges
  for this purpose only.
- **AC-INT-02 interpretation.** "Head-on in a one-way (single-lane) aisle": with
  corridor reservation a straight single-lane corridor never deadlocks (B waits at
  the entrance; tested). The acceptance tests therefore use a corridor split by a
  side spur, where both agents can enter their own segment and meet at the
  junction.
- **Location work.** Capacity per location with FIFO queues (`space` blocking);
  co-location penalty `1 + penalty_per_agent x others in group`, applied at
  service start; locations with `occupies_edge` make the worker a stationary
  occupant of that edge.
- **Disruptions on the facility.** `location_blocked` on an edge/zone/node blocks
  edges (routes avoid them; agents with no route wait as `no_route`), on a
  location sets its capacity to 0; `location_degraded` scales edge speeds;
  `capacity_change` overrides a location's capacity. The manifest itself never
  changes (FR-FAC-03).

## Consequences
- Results are deterministic and fast (4 h warehouse shift: about 1 s).
- Mid-edge re-timing and continuous-space conflicts are out of scope for
  `logical`; `kinematic` mode (M4) and calibration (FR-INT-05) address fidelity.
