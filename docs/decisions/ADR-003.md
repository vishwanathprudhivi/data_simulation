# ADR-003: RNG stream derivation and determinism mechanics

- **Status:** Accepted
- **Requirements:** FR-ENG-06, FR-EXP-01/02, FR-DSP-03, NFR-01, BRD 7.3, AC-ENG-02, AC-EXP-02

## Decision
- Each named stream is `Generator(PCG64(SeedSequence(entropy=master_seed,
  spawn_key=(replication_id, sha256(stream_name)[:8] as int))))`. Streams are
  independent and creation order does not matter; CRN = same
  `(master_seed, replication_id)` across alternatives.
- Core stream names: `demand` (default for a demand source; each source names its
  own), `service_time`, `agent_speed`. Domains add their own (e.g. `travel`).
- Future-event list key `(time, priority, seq)`; `seq` is a scheduling counter.
  Dispatch requests at one instant are coalesced into a single decision event
  with priority after releases/completions.
- The event log records no wall-clock values; its `data` column is canonical JSON
  (sorted keys). Parquet is written with zstd and fixed writer options, so the
  same config + seed + library versions give byte-identical `events.parquet`.
- Wall-clock time is read only in `Engine.run` for the real-time factor in
  `meta.json`.

## Consequences
- NumPy's distribution algorithms may change across major versions; versions are
  recorded in `meta.json["versions"]` and form part of the reproducibility key.
- Stochastic demand draws the next arrival's attributes when it is scheduled, so a
  `demand_surge` affects arrivals scheduled after it starts (one in-flight arrival
  keeps its original gap). Documented and acceptable for v1.
