# ADR-001: Isaac Sim version pin (provisional)

- **Status:** Accepted (provisional; re-confirm at the start of M4)
- **Requirements:** BRD 7.4 [DECISION NEEDED], Q1, NFR-05

## Context
The BRD asks us to pin an Isaac Sim version in M0 after checking the target
environment. The M0/M1 development environment is a CPU-only container with no
GPU and no Isaac Sim install, so the target machine could not be checked.

## Decision
- Target **Isaac Sim 5.0.0** (standalone Python workflow, headless via
  `isaacsim.SimulationApp`), whose bundled interpreter is Python 3.11.
- The pin lives in one place: `simcore.adapters.omniverse.compat.ISAAC_SIM_VERSION`.
  All version-specific imports and calls go in `adapters/omniverse/compat.py`.
- The engine itself supports Python >= 3.10 so the adapter can run inside
  Isaac's interpreter while `logical` mode runs anywhere.

## Consequences
- M4 must verify the pin on the target GPU machine and update this ADR (and the
  shim) if a different 4.x/5.x release is installed there.
- No other module may import `omni`, `isaacsim` or `pxr` (import-linter contract
  and `tests/unit/test_architecture.py`).

## Update (M4)
The adapter (`simcore.adapters.omniverse`) is implemented against the 5.x
standalone API (`isaacsim.SimulationApp`, `omni.usd.get_context()`, `pxr.UsdGeom`)
behind `compat.StageAPI`. It has **not** been run on Isaac Sim yet; the first GPU
session must run `make test-isaac` and record the outcome here.
