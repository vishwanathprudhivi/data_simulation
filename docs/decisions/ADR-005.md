# ADR-005: Config conventions: units, inheritance, overrides, errors

- **Status:** Accepted
- **Requirements:** BRD 7.1, FR-SCN-05, FR-ENG-08, FR-EXP-03, FR-SCG-01

## Decision
- **Units.** Numbers are SI. Quantity fields also accept strings with a unit
  (`"30 min"`, `"2.4 m"`, `"1.1 m/s"`), converted once at load. Distribution
  specs accept a `unit` for their location/scale parameters, converted at load.
- **References.** `extends`, `facility`, `behaviors` and replay `path` are
  resolved relative to the file that contains them. Config hashes exclude file
  locations (contents are hashed instead), so moving a project does not change
  hashes.
- **Inheritance (`extends`).** Mappings deep-merge. Lists whose items are all
  mappings keyed by `id` / `agent_type` / `stream` / `name` merge item-by-item by
  key (new items append); other lists are replaced.
- **Override paths** (experiments, levers, CLI `--set`): dotted paths where a
  list segment is an index or an item key, e.g. `fleet.server.count`,
  `demand.demand.interarrival.mean`, `disruptions.outage.at`.
- **Errors.** All validation problems are collected into one `ConfigError`;
  each line gives file, field path, message (with the offending value) and a fix.
- **CLI framework:** `click`.
